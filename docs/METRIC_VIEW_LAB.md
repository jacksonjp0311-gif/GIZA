# GIZA v0.10.6 // METRIC VIEW LAB

METRIC VIEW LAB is designed around one refusal:

> **No real plan registration = no metric sightline.**

The previous Visibility Lab legitimately computed topology: depth, branch points, merge points, articulation points and qualitative environment transitions. It did not have wall polygons, door openings, wall heights or registered plan coordinates. v0.10.6 therefore keeps the actual metric-ray count at **zero**.

Workflow progress percentages shown in the UI are **not confidence scores**.

## Ray contract

Real rays become legal only after:

- source-byte custody and SHA-256;
- metric plan registration with controls and holdouts;
- wall polygons and doorway/opening geometry;
- explicit observer and target heights;
- explicit/bounded occluder heights;
- sensitivity runs.

Future outputs may include visibility polygons, doorway cones, statue-field visibility, route reveal timing and bounded sunlight-aperture tests. None of these will automatically infer ritual meaning.

## v0.10.7 frame separation

Metric visibility now distinguishes **plate-local** and **plateau-global** authority. An accepted `PLATE_LOCAL_METERS` registration is sufficient for intra-building wall/opening geometry and visibility rays. It cannot establish GPMP placement, monument-to-monument alignments, or vertical datum.

This removes a false dependency: room-scale visibility does not have to wait for the entire plateau geodetic bridge.
